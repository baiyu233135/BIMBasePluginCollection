一、我的需求（按对话顺序）
--------------------------
  ① 画板按钮快捷键提示不要（后又改主意：保留提示，仅记录取舍过程）。
  ② 画板命令行输入命令名回车无法调用命令。
  ③ 延伸/拉伸/偏移/合并/倒斜角/圆角/分解/等分 8 个命令点击无效果（历史遗留，
     之前就是坏的），不需要 CAD 级全面支持，简单实现即可。
  ④ 导入 DWG 识别三视图后，同步到 BIMBase 输入坐标位置不对（反复多轮）。
  ⑤ 选中布置后的组件无法读取位置来做相对布置（"在选中的组件上面900mm布置桥墩"）。
  ⑥ AI 语音"把画板组件同步到一万一万一万的位置"位置不正确。


二、最终状态（全部实测通过 2026-09-07）
--------------------------------------
  1. 快捷键提示：先剥离后恢复，最终保留（按钮显示"直线 (L)"等）；
     命令行新增命令名激活（TR/延伸/中文名均可回车激活），坐标/参数输入不受影响。
  2. 8 个修改命令全部可用：
     - 延伸：重写为单步（点线哪端，哪端延伸到最近交点）
     - 拉伸：修 _sel_box 恒真 bug（点选路径解包 None 被静默吞）
     - 偏移：默认距离 20→10mm，命令行可改
     - 倒斜角/圆角：重写为点选两线 + 命令行输距离/半径（原实现依赖内嵌环境
       不可用的模态弹窗 QInputDialog，且圆角有修剪方向反的真 bug）
     - 合并/分解/等分：证伪实验确认原逻辑可用，是流程没人懂造成的假失效
     - 离线桩件回归 12/12（archive/test_modify_commands.py），
       命令名激活 6/6（archive/test_cmd_name_activation.py）
  3. 识别三视图同步位置（5 轮排查，根因逐层揭开）：
     - 第 1 层：识别构件（pdf_recognized）有独立的二次弹窗 + 同步 origin 重复叠加
       → 修复：识别构件锚点=同步基准坐标，不再二次弹窗
     - 第 2 层：门式桥墩等 4 个复杂构件走"生成代码缓存"路径，只读 pdf_anchor
       不读 origin → 修复：4 条路径一律 origin 优先
     - 第 3 层：重同步只删实例数据不删图形实体 → 旧组件残留成"幽灵"，
       用户误选幽灵读到旧位置 → 修复：删除实例时连带删绑定图形实体
       （get_allbinding_entity_from_instance + delete_one_entity）
     - 第 4 层：诊断代码对 P3DInstanceKey 字符串化触发 _data 崩溃，
       污染整个 SDK 会话导致位置读取全挂 → 撤掉诊断代码（教训见下）
     - 第 5 层：place_component_at 烘焙坐标进偏移参数后，create_geometry 失败
       时兜底的 _PlaceToDirect/place_to 又叠加 translate → 双重偏移落到 2 倍坐标
       → 修复：烘焙后兜底一律恒等变换（AI_Modeling/component_factory.py）
  4. AI 同步指令坐标解析：中文数字"一万一万一万"→(10000,10000,10000)
     （_cn_to_num + 按"万"切分），解析失败弹手动输入框（复用画板基准坐标弹窗），
     不再静默同步到错误位置。
  5. 识别三视图场景"只同步 3D 构件"：识别构件打 _recognized_component 标记，
     全部同步时跳过图纸线条（三视图在画板是摊开排版的，同步过去无意义）。


三、关键技术细节与教训
----------------------
  1. 证伪实验的价值：8 个"坏"命令里 7 个逻辑能跑通，真坏的只有倒斜角/圆角。
     先用 FakeBoard 桩件离线驱动验证，再决定重写还是保留——避免过度重写。
  2. P3DInstanceKey.__str__ 有 _data 崩溃 bug，且崩溃后 get_noumKV 全挂需重启
     进程。诊断/日志代码严禁对 key 做 str/repr/bool 之外的……不行，连 bool 都要小心，
     最稳的是完全不碰、只记录类型名。
  3. "坐标烘焙"与"变换放置"二选一：place_component_at 的 bake=True 把坐标写进
     偏移X/Y/Z 参数（几何直接建在目标点），后续任何放置路径都必须用恒等变换。
     两条路同时用 = 双重偏移。这是本轮最隐蔽的 bug。
  4. 重同步删组件要删两层：实例数据（delete_data_bydatakey）+ 绑定图形实体
     （delete_one_entity），只删数据会留幽灵。
  5. 语音数字解析：中文口语"一万一万一万"=三个一万，按"万"切分逐组转换；
     解析不出来宁可弹窗问用户，也不静默放错位置。
  6. 本轮同步涉及的改动文件：速构智维/bimbase_sync.py、board.py、
     utils/ai_panel.py、utils/ai_executor.py、AI_Modeling/component_factory.py、
     AI_Modeling/bimbase_modifier.py（高度辅助函数加了又按用户意见撤掉，
     "上方"保持底面+距离语义）。
