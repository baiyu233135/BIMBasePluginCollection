二、根因分析
------------
1. 【核心】组件类定义位置错误：
   AI_Modeling/bimbase_sync.py 文件头注释明确要求"所有组件类必须在此文件中
   定义，BIMBase 才能通过 sys.argv[0] 找到它们"（DependentFile 序列化机制）。
   圆柱等基础组件都遵守了，但 pier 是 component_factory.py 的
   _load_complex_component() 从 组件测试/引桥桥墩.py 动态加载到合成模块
   `_ai_modeling_complex_pier` 下，BIMBase 序列化时找不到该类：
   - create_geometry 报 'GeTransform' object cannot be interpreted as an integer
   - _PlaceToDirect 静默失败（get_place_to_entityId: ModelId=-2, valid=False）
     却误报 SUCCESS，注册表拒绝登记（instance_key is None）
   对照：CADBoard 能成功放桥墩，是因为 ApproachPierComponent 定义在
   CADBoard/bimbase_sync.py:1179 模块级别。
2. 放置结果无校验：place_component_at 对 _PlaceToDirect/place_to 路径不验证
   实体是否真的创建，失败也报成功，不会继续走 SendInput 兜底。
3. 修改链路不认桥墩：bimbase_modifier.py 的 infer_component_type_from_params
   只认基础几何体参数键，桥墩参数集推断为 None → replace_noumenon 主路径
   直接返回"无法推断组件类型"。
4. 参数污染：动态加载把 \x07_transformation 等内部键读进 defaults；解析器对
   "墩高2000"还会经通用"高"模式额外套出 height=2000 伪参数。


三、已完成的修改
----------------
1. AI_Modeling/bimbase_sync.py
   - pyp3d 导入补充 rotate、Combine（含 ImportError 占位）。
   - 新增 _log() 调试日志助手（写 ai_modeling_debug.log）。
   - 模块级新增 ApproachPierComponent 类：移植自
     CADBoard/bimbase_sync.py:1179-1290（已实测可用版本），与
     组件测试/引桥桥墩.py 几何逻辑一致的精简 7 参数版
     （盖梁总长1930/盖梁总高300/盖梁宽300/墩柱直径250/墩柱间距1140/
      墩高1200/系梁根数2），含盖梁布尔差失败回退实体截面、
     replace() 异常回退 Cube()。

2. AI_Modeling/ai_modeling/component_factory.py
   - 从 bimbase_sync 导入 ApproachPierComponent，注册 COMPONENT_CLASSES['pier']
     与 COMPONENT_DEFAULTS['pier']；_infer_component_type_from_comp 的
     name_map 增加 'ApproachPierComponent': 'pier'。
   - bimbase_sync 的导入改为不再要求 _pyp3d_ok（其自带占位回退，可离线导入），
     保证注册表完整、便于离线测试。
   - 删除 pier 的 _load_complex_component() 调用（anchor 保持动态加载不变）。
   - _get_valid_kwargs：__init__ 含 **kwargs（VAR_KEYWORD）时放行全部参数
     （原实现会把 pier 的参数全部过滤掉）。
   - 新增 _filter_component_params() + _COMPONENT_ALLOWED_KEYS：pier 只保留
     7 个核心参数 + 偏移X/Y/Z，create_component 合并参数时过滤伪键/内部键。
   - place_component_at 新增放置校验：_count_entities()（get_all_entityid
     计数）+ _verify_new_entity()（实体数增加或 get_place_to_entityId 有效
     才算成功）；_PlaceToDirect 与 place_to 路径校验失败会继续走
     SendInput 模拟点击 → place() 手动兜底，不再"假成功"。

3. AI_Modeling/ai_modeling/bimbase_modifier.py
   - infer_component_type_from_params：新增 pier（盖梁总长/墩柱间距/系梁根数）
     与 anchor（锚块总长/底柱半径/承台长度）识别。
   - modify_instance_by_key 方式1（replace_noumenon）：参数推断失败时回退
     查 ComponentRegistry 记录的 component_type。
   - 方式2（get_noumenon_from_datakey）：仅当 k in noum 时才写入，跳过
     height 等不属于该组件的伪参数。

4. AI_Modeling/ai_modeling/command_parser.py（汉字数字支持，本轮追加）
   - 起因：用户实测“以原点为起点，沿y轴方向间隔20米放置五个桥墩”，
     “五个”未识别，按默认 2 个放置。
   - parse() 入口新增 _replace_chinese_numerals()：把 零一二两三四五六七
     八九十百千万 组成的汉字数字段转为阿拉伯数字（支持 万 分段、
     十/百/千 组合，如 十五->15、三百二十->320、二十米->20米）。
   - _extract_route_spacing() 数量提取分级：优先“共 N 个”，其次
     “生成/放置/布置 N 个”，最后通用“N 个”回退（修复“布置一个…共5个”
     被“1个”抢先匹配的问题）。
   - 注意：“一个”会被转成“1个”，对阵列/路线数量的语义更准确；
     “三百五”这类口语省略（=350）按字面解析为 305，暂不支持。

四、技术栈与关键实现
--------------------
运行环境：
  - BIMBase 2025，Python 3.7.9 嵌入式解释器
  - pyp3d SDK v18446497937724801024（Release 2024.10）

关键机制（本轮再次验证的经验）：
  - BIMBase 放置参数化组件时通过 DependentFile（sys.argv[0] 指向的文件）
    反查组件类；类必须定义在该文件模块级，动态加载的合成模块无法被序列化。
  - _PlaceToDirect/place_to 可能"静默失败"：调用不抛异常但实体未创建，
    必须用实体计数或 get_place_to_entityId 校验后再报成功。
  - 解析器通用参数模式（高/长/宽）会对复杂组件指令产生伪参数，
    应在写入组件前按组件允许的键集过滤，而不是在解析器里特殊化。

关键文件：
  - AI_Modeling/bimbase_sync.py                 组件类定义（DependentFile）
  - AI_Modeling/ai_modeling/component_factory.py 创建/放置/注册
  - AI_Modeling/ai_modeling/bimbase_modifier.py 修改已有实例
  - AI_Modeling/ai_modeling/command_parser.py   本地指令解析
  - AI_Modeling/test_pier_parse.py              离线回归测试
  - 调试日志：AI_Modeling/ai_modeling_debug.log
