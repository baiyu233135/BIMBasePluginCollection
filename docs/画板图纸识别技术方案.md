# 画板图纸识别技术方案

## 一、背景与目标

### 1.1 背景

当前 `数据参考源/` 目录下有两个关键数据文件：

- `索缆锚锭，引桥桥墩.pdf`：包含两个桥梁组件的三视图和尺寸标注，但**是扫描件/图片型 PDF，没有矢量数据**。
- `桥.dwg`、`索.dwg`：DWG 内部只有 `PDFREFERENCE` 实体，**引用外部 PDF，没有 CAD 几何数据**。

因此，无法直接通过 DWG 矢量解析获取参数，必须采用**图像识别 + OCR + 规则推理**的方式从 PDF/图片中提取构件参数。

### 1.2 目标

让 CADBoard 画板能够：

1. 导入 PDF/DWG 工程图纸。
2. 识别出图纸中的桥梁组件类型（如索缆锚锭、引桥桥墩）。
3. 提取关键尺寸参数。
4. 与组件库匹配，生成参数化 3D 模型。
5. 在画板中生成三视图，并支持参数面板修改。
6. 支持 AI 对话布置或手动点击布置。

## 二、技术方案

提供两种方案：**方案 A 联网多模态 LLM** 和 **方案 B 本地化**。两者结合使用，互为补充。

### 方案 A：联网多模态大模型（推荐作为主力方案）

#### 核心思路

利用多模态大语言模型直接理解工程图纸图片，输出结构化的构件参数。

```text
PDF 转高清图片
    ↓
多模态 LLM（GPT-4o / DeepSeek-VL / Qwen-VL-Max）
    ↓
输出 JSON：{构件类型, 三视图说明, 参数列表}
    ↓
规则引擎校验尺寸一致性
    ↓
匹配组件库 / 创建新组件
    ↓
pyp3d 生成 3D 模型 + 三视图
```

#### 推荐模型

| 模型 | 优势 | 劣势 | 适用场景 |
|---|---|---|---|
| **GPT-4o** | 图像理解能力最强，工程图识别准确率高 | 需要翻墙和 API 费用 | 复杂图纸、高精度识别 |
| **DeepSeek-VL** | 中文理解好，性价比高 | 图像理解能力略逊于 GPT-4o | 中文工程图、成本敏感 |
| **Qwen-VL-Max** | 阿里系，中文和表格识别强 | 多模态 API 稳定性需验证 | 中文图纸、尺寸表格 |

#### 提示词策略（Prompt Engineering）

```text
你是一位桥梁工程图纸识别专家。请分析这张工程图纸，识别其中的桥梁构件类型和三视图，并提取关键尺寸参数。

要求：
1. 判断构件类型：索缆锚锭 / 引桥桥墩 / T梁 / 箱梁 / 其他。
2. 说明三视图布局（主视图、俯视图、左视图的位置）。
3. 提取所有带尺寸标注的数字和单位。
4. 输出标准 JSON 格式：
{
  "component_type": "索缆锚锭",
  "views": {"front": "主视图", "top": "俯视图", "left": "左视图"},
  "parameters": {
    "锚碇高度": {"value": 2000, "unit": "mm"},
    "锚碇底宽": {"value": 2200, "unit": "mm"},
    ...
  },
  "notes": "本图尺寸以 cm 计，已转换为 mm"
}
```

#### 优势

- 开发速度快，不需要训练模型。
- 对复杂工程图理解能力强。
- 可以直接输出结构化数据。

#### 劣势

- 依赖网络和多模态 API。
- 可能产生幻觉（提取错误尺寸）。
- 有 API 调用成本。

### 方案 B：本地化 OCR + 传统 CV + 小模型

#### 核心思路

不依赖联网大模型，使用本地 OCR 和计算机视觉技术提取图纸信息。

```text
PDF 转高清图片
    ↓
OpenCV 预处理（灰度、二值化、去噪）
    ↓
图框分割与三视图区域识别
    ↓
PaddleOCR 提取文字和数字
    ↓
尺寸线/箭头检测（传统 CV）
    ↓
规则引擎关联数字与尺寸线
    ↓
匹配组件库 / 创建新组件
    ↓
pyp3d 生成 3D 模型 + 三视图
```

#### 关键技术栈

| 技术 | 用途 |
|---|---|
| **PaddleOCR** | 中文文字和数字识别 |
| **OpenCV** | 图像预处理、轮廓检测、直线检测、图框分割 |
| **Qwen-VL / InternVL（本地）** | 可选，用于复杂图纸理解 |
| **规则引擎** | 尺寸校验、构件类型匹配、参数推理 |

#### 优势

- 不依赖网络，保护图纸隐私。
- 无 API 调用成本。
- 对简单图纸效果稳定。

#### 劣势

- 开发工作量大。
- 复杂图纸（如遮挡、低质量扫描件）识别率低。
- 需要针对工程图优化 OCR 和 CV 流程。

### 两种方案结合使用

| 场景 | 使用方案 |
|---|---|
| 首次识别复杂图纸 | 方案 A（多模态 LLM）快速出结果 |
| 结果校验和修正 | 方案 B（OCR+CV）辅助验证关键尺寸 |
| 无网络环境 | 方案 B（本地化） |
| 批量处理同类图纸 | 方案 B 或微调本地模型 |

## 五、三视图生成

复用 `CADBoard/geometry/faces.py` 的现有能力：

- 为每个参数化组件定义 `FACE_TEMPLATES`（俯视图、主视图、左视图）。
- 调用 `FaceManager.generate_all_faces(mode='三视图')` 自动布局。
- 用户修改参数面板时，联动更新三视图。

对于索缆锚锭和引桥桥墩，需要补充对应的面模板。

## 七、推荐实施路线

### 第一阶段：基础能力建设（当前）

1. ✅ 创建索缆锚锭、引桥桥墩参数化组件。
2. ✅ 配置组件测试插件按钮和图标。
3. 补充 `CADBoard/geometry/faces.py` 中这两个组件的三视图模板。

### 第二阶段：图纸识别 MVP

1. 实现 PDF 转图片模块。
2. 接入一种多模态 LLM API（建议先 DeepSeek-VL 或 Qwen-VL-Max）。
3. 实现 LLM 输出解析为结构化参数。
4. 实现参数到组件的映射和实例化。
5. 在 CADBoard 中添加"识别三视图"按钮。

### 第三阶段：本地化能力建设

1. 集成 PaddleOCR 提取图纸文字和数字。
2. 用 OpenCV 实现尺寸线检测和图框分割。
3. 建立规则引擎校验 LLM 输出。
4. 实现无网络环境下的降级识别。

### 第四阶段：工作流整合

1. 把识别流程封装为 CADBoard 命令。
2. 接入 AI 对话面板，支持自然语言驱动。
3. 输出识别报告和参数 Excel。

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| LLM 幻觉提取错误尺寸 | 规则引擎校验 + OCR 辅助验证 |
| PDF 扫描质量差 | 图像增强预处理 |
| DWG 无几何数据 | 统一转为图片处理 |
| pyp3d 布尔运算不稳定 | 用颜色/几何组合代替布尔减 |
| 构件类型不在组件库中 | 提示用户新建组件或选择最接近类型 |

## 十、结论

推荐采用 **"方案 A 为主、方案 B 为辅"** 的混合策略：

- 先用联网多模态 LLM 快速实现图纸识别 MVP。
- 同时用本地 OCR+CV 做关键尺寸校验。
- 逐步积累规则和本地模型能力，最终实现无网络环境下的稳定识别。

目前已完成基础参数化组件建设，为后续图纸识别提供了目标组件和测试入口。
