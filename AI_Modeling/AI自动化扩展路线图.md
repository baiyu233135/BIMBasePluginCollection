# BIMBase AI 智能建模 — 扩展功能路线图

基于当前项目架构和 BIMBase/pyp3d 能力边界，以下是可行的 AI 自动化扩展方向。

---

## 🔥 立即可做（复用现有架构，1-2 天实现）

### 1. 自然语言批量编辑（修改已创建实体）
**场景**：选中一个或多个组件，输入"把半径改成 200"、"高度加 50%"、"所有柱子加粗 20"

**技术基础**：
- `replace_noumenon_python_new(temp, instancekey)` 可以更新已有实例的几何
- `get_all_entityid()` / `get_current_entityId()` 可以获取选中实体
- `python_transformation_operation()` 可以移动/缩放已有实体（在交互上下文外不行，但修改参数可能可以）

**实现思路**：
1. 在 `ai_window.py` 中检测用户输入的是"修改"类指令
2. 调用 `get_all_entityid()` 获取当前选中实体
3. 解析用户意图（改哪个参数、改多少）
4. 通过 LLM 生成参数修改代码或直接操作组件属性

**价值**：⭐⭐⭐⭐⭐ — 最常用的功能之一

---

### 2. 智能阵列（超越基础矩形阵列）
**场景**："沿圆形排列 8 根柱子"、"沿这条线每隔 500 放一个灯"、"螺旋上升排列"

**技术基础**：
- `array_generator.py` 已有基础矩形阵列
- 数学计算简单（极坐标、等距分布、螺旋线）

**扩展类型**：
| 阵列类型 | 描述 |
|---------|------|
| 圆形阵列 | 绕中心点均匀分布 |
| 路径阵列 | 沿曲线/多段线等距分布 |
| 螺旋阵列 | 螺旋上升排列 |
| 随机散布 | 在区域内随机分布（带碰撞检测）|
| 镜像阵列 | 沿某轴镜像复制 |

**价值**：⭐⭐⭐⭐ — 建筑建模高频需求

---

### 3. 多轮对话上下文
**场景**：
```
用户：在 (1000,2000,500) 画一个圆柱
AI：已创建圆柱
用户：再高一点          ← AI 知道是修改刚才的圆柱
用户：复制 3 个到右边    ← AI 知道复制的是这个圆柱
```

**技术基础**：
- 在 `AIModelingWindow` 中保存 `last_created_entity` / `last_operation`
- LLM prompt 中加入上下文历史

**实现思路**：
1. 每次成功创建实体后，记录 `entity_id` + `component_type` + `params`
2. 后续指令中，如果缺少主语，默认操作上一个实体
3. LLM prompt 中附加上一轮的参数，让模型生成增量修改

**价值**：⭐⭐⭐⭐⭐ — 极大提升交互体验

---

### 4. 预设模板库
**场景**：一键生成标准建筑元素

**模板示例**：
```
"生成标准会议室" → 房间+桌子+椅子+投影幕布
"生成标准楼梯" → 根据层高自动计算踏步数
"生成标准机房" → 机柜+空调+配电箱按规范排布
"生成停车位" → 根据场地尺寸自动排列车位线
```

**技术基础**：
- 就是多个 `create_component` + `place_component_at` 的组合
- 可以封装为 `TemplateLibrary` 类

**价值**：⭐⭐⭐⭐ — 减少重复劳动

---

## 🚀 中等难度（需要一定开发量，1-2 周）

### 5. 选中实体 → AI 识别 → 自然语言修改
**场景**：在 BIMBase 中选中一个组件，然后在 AI 对话框中说"把这个改成红色的"

**技术基础**：
- `get_current_entityId()` 获取当前选中实体
- `get_modelid_entityid_relation()` 获取模型关系
- 需要理解 BIMBase 的材质/属性系统

**挑战**：
- pyp3d 中材质/颜色相关的 API 需要进一步研究
- 需要把 entityId 映射回组件参数

**价值**：⭐⭐⭐⭐⭐ — 丝滑的工作流

---

### 6. 智能对齐与分布
**场景**：
```
"把这三个柱子底面对齐"
"让这些灯等间距排列"
"把桌子居中放到房间里"
```

**技术基础**：
- `get_all_entityid()` 获取多个实体
- 计算边界框（bounding box）
- `python_transformation_operation()` 移动实体（如果能在某种模式下工作）
- 或者通过修改组件的 `偏移X/Y/Z` 参数来间接移动

**挑战**：
- 需要获取实体的当前位置（查询 API）
- 对齐逻辑需要处理多种情况（中心对齐、边对齐、等距分布）

**价值**：⭐⭐⭐⭐ — 常用但实现较繁琐

---

### 7. 工程量 AI 助手
**场景**：
```
"计算所有圆柱的总体积"
"这个房间有多少面积"
"统计模型里有多少根柱子"
```

**技术基础**：
- `get_all_entityid()` 获取所有实体
- 需要查询每个实体的几何属性（体积、面积、长度）
- pyp3d 中可能有相关查询 API（需要进一步探索）

**价值**：⭐⭐⭐ — 实用但非核心建模功能

---

### 8. 语音输入支持
**场景**：用户对着麦克风说"在中心画一个半径 500 的球"，直接执行

**技术基础**：
- 集成语音识别库（如 `speech_recognition`、`whisper`）
- 把语音转文字后，走现有的文本解析流程

**实现思路**：
1. 在 `ai_window.py` 中添加麦克风按钮
2. 点击后录制音频
3. 调用 Whisper API 或本地模型转文字
4. 文字送入现有的 `_send_message()` 流程

**注意**：
- 嵌入式 Python 3.7.9 中安装 whisper 可能有依赖问题
- 也可以调用在线 API（百度语音、讯飞等）

**价值**：⭐⭐⭐ — 酷炫但非刚需

---

## 🔮 高难度（需要深入研究或外部依赖）

### 9. DWG 图纸 → 3D 模型（AI 识图建模）
**场景**：导入 CAD 平面图，AI 自动识别墙、柱、门窗，生成 3D BIM 模型

**技术基础**：
- DWG 解析库（如 `ezdxf`）
- 图像/矢量识别（AI 识别线条含义）
- 从 2D 轮廓生成 3D 实体（拉伸）

**挑战**：
- DWG 格式复杂，解析困难
- 需要训练或调用专门的建筑图纸识别 AI
- BIMBase 的 `ImportSU`、`P3D.exportdwg` 等命令也许能辅助

**价值**：⭐⭐⭐⭐⭐ — 革命性功能，但实现难度极高

---

### 10. 点云 → BIM 模型（Scan-to-BIM）
**场景**：导入激光扫描点云（PCD/PLY），AI 自动识别墙面、柱子、管道，拟合为参数化几何体

**技术基础**：
- `PCDImport.dll` 说明 BIMBase 支持点云导入
- Open3D 库可以做点云分割和平面拟合
- 拟合后的几何可以用现有组件工厂生成

**挑战**：
- 点云处理计算量大
- 嵌入式 Python 3.7 中安装 Open3D 困难
- 需要专业的点云分割算法

**价值**：⭐⭐⭐⭐⭐ — 行业热点，但投入巨大

---

### 11. AI 合规检查
**场景**：
```
"检查所有柱子的间距是否满足防火规范"
"检查楼梯踏步高度是否符合标准"
"找出模型里所有碰撞"
```

**技术基础**：
- `BIMBase.Tool.ClashDetectionNew` 命令可以做碰撞检测
- 规则可以用代码硬编码或 LLM 判断
- 需要遍历模型中的所有实体并获取属性

**价值**：⭐⭐⭐⭐ — 专业性强，适合特定行业用户

---

### 12. AI 生成复杂参数化组件
**场景**：用户描述一个复杂形状，AI 生成对应的 pyp3d 组件代码

**示例**：
```
"生成一个 twisted tower，底部半径 500，顶部半径 200，高度 3000，扭转 90 度"
→ AI 生成自定义的 Component 类，包含扭转逻辑
```

**技术基础**：
- 现有的 `bimbase_sync.py` 已经展示了如何写自定义组件
- LLM（DeepSeek）可以生成 Python 几何代码
- 把生成的代码动态写入 `bimbase_sync.py` 或临时文件

**挑战**：
- 需要确保生成的代码语法正确、能正确导入
- 复杂几何可能需要大量数学计算
- 每次生成新组件需要处理 DependentFile 的更新

**价值**：⭐⭐⭐⭐ — 想象空间巨大

---

## 📋 建议的优先级排序

| 优先级 | 功能 | 理由 |
|--------|------|------|
| **P0** | 多轮对话上下文 | 提升现有体验，代码改动小，用户感知强 |
| **P0** | 自然语言批量编辑 | 高频需求，复用现有实体创建逻辑 |
| **P1** | 智能阵列扩展 | 建筑建模核心功能，数学实现清晰 |
| **P1** | 预设模板库 | 组合现有能力，减少重复操作 |
| **P2** | 选中实体 + AI 修改 | 工作流闭环，但需要研究实体属性查询 API |
| **P2** | 工程量 AI 助手 | 实用，但依赖查询 API 的完善程度 |
| **P3** | 语音输入 | 酷炫但非刚需，依赖外部 API |
| **P3** | DWG/点云识图 | 长期方向，投入大 |

---

## 🔧 架构层面建议

为了支持上述扩展，建议对现有代码做以下重构：

1. **组件工厂扩展为 PluginRegistry**
   - 不仅创建基础几何，还注册自定义组件类
   - 支持动态加载用户定义的组件脚本

2. **命令解析器升级为 IntentEngine**
   - 不仅解析"创建"意图，还要支持"修改""删除""查询""对齐"等
   - 使用更结构化的 prompt，让 LLM 输出统一的 action JSON

3. **会话状态管理**
   - `SessionManager` 保存最近 N 步的操作历史
   - 支持 undo/redo、上下文引用

4. **实体查询层**
   - 封装 `get_all_entityid()`、`get_entity_property()` 等查询 API
   - 提供按类型、按位置、按属性筛选实体的能力
