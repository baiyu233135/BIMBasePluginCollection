# CADBoard 报错处理记录

## 1. CAD画板启动后闪退

### 现象

点击“CAD画板”按钮后，窗口一闪即逝。

### 原因

- PyQt 插件路径未正确设置。
- BIMBase 进程 PID 绑定失败。
- Python 环境缺少依赖。

### 处理方法

1. 检查 `main.py` 中是否设置了正确的 Qt 插件路径。
2. 运行 `utils/bimbase_pid.py` 修复 PID 绑定。
3. 运行 `setup_env.py` 安装缺失依赖。

## 2. 与 BIMBase 不同步

### 现象

CAD画板中绘制的图元无法同步到 BIMBase，或 BIMBase 中选中的组件无法同步到 CAD画板。

### 原因

- BIMBase 进程 PID 变化。
- COM/IPC 连接失败。
- 组件注册表 `component_registry.json` 数据不一致。

### 处理方法

1. 确保 BIMBase 只启动一个实例。
2. 删除 `component_registry.json` 后重新同步。
3. 检查 `utils/bimbase_sync.py` 中的同步逻辑。

## 3. DWG/PDF 导入失败

### 现象

导入 DWG 或 PDF 后没有图元，或报错。

### 原因

- 缺少 `ezdxf` 或 `PyMuPDF`。
- 文件格式不兼容。
- 坐标单位或比例设置错误。

### 处理方法

1. 安装依赖：`pip install ezdxf PyMuPDF`。
2. 使用简单文件测试，逐步增加复杂度。
3. 在 `utils/dwg_handler.py` 或 `pdf_handler.py` 中调整单位转换系数。

## 4. AI 智能建模无法启动

### 现象

点击“AI智能建模”后没有弹出窗口。

### 原因

- `AI_Modeling/` 目录不存在或路径错误。
- `ai_config.json` 中 API Key 无效。

### 处理方法

1. 确认 `AI_Modeling/main.py` 存在。
2. 检查 `ai_config.json` 配置。
3. 手动运行 `python AI_Modeling/main.py` 查看报错。

## 5. 桥梁病害识别检测不到病害

### 现象

选择图片后运行检测，没有框出任何病害。

### 原因

- 图片质量问题。
- 模型权重不匹配。
- 置信度阈值过高。

### 处理方法

1. 使用清晰度更高的照片。
2. 确认加载了正确的 `yolov8n.pt` 权重。
3. 在 `utils/disease_detector.py` 中降低 `conf` 阈值。

## 6. 自动配置环境失败

### 现象

点击“自动配置环境”后提示安装失败。

### 原因

- 网络问题导致 pip 无法下载。
- BIMBase 安装路径未找到。
- 权限不足。

### 处理方法

1. 检查网络连接，尝试使用手机热点。
2. 手动指定 BIMBase 安装路径。
3. 以管理员权限运行 BIMBase 或脚本。

## 7. 崩溃日志

如果 CADBoard 崩溃，会在目录下生成 `*_CRASH.txt` 文件。打开后查看 Python 堆栈信息，定位崩溃位置。

## 8. 执行 AI 建模指令后，画板"同步到BIMBase"失败

### 现象

先在 AI 面板执行了建模指令（如"放一个桥墩"），之后手动画的组件点击"同步到BIMBase"失败，日志 `bimbase_sync_debug.log` 中出现：

```text
TypeError.'module' object is not callable
[pyp3d.nonstatic_call_forwarding]
[BPParametricComponent.BPParametricComponentManager::create]
```

### 原因

`ai_modeling_launcher._load_ai_main()` 在加载 AI_Modeling 时会把其目录插到 `sys.path[0]` 并删除 `sys.modules` 中的 `bimbase_sync`/`component_registry` 缓存。执行结束后未恢复，导致画板同步时 pyp3d 回调按模块名 `bimbase_sync` 解析组件类，拿到的是 AI_Modeling 的同名模块（其中没有画板的组件类）。

### 处理方法

已在 `ai_modeling_launcher.py` 的 `execute_modeling_action()` / `execute_callback_in_ai_window()` 中加入模块环境快照/恢复（finally 中还原 `sys.path` 和 `sys.modules`）。若旧版本遇到此问题，重启 BIMBase 即可恢复模块环境。

## 9. 建模指令中"不要位置参数"/"单位m"/上色未生效

### 原因与处理（均已修复）

- "不要位置参数"未识别：关键词正则只覆盖"不写入/不写位置"等写法 → 已改为 `(不|别)(要|用|需)?(写入|记录|带|加)?(位置|坐标)` 通配。
- "单位m"未换算：整体声明正则中"用/是/为"非可选 → 已改为可选，支持"单位m"/"单位：厘米"等写法。
- 上色后组件仍是默认色：颜色原在创建后对几何染色，但 `place_component_at` 内部会再次 `replace()` 重建几何把颜色覆盖 → 已改为组件类 `replace()` 末尾统一读取 `颜色` 属性上色（`AI_Modeling/aim_bimbase_sync.py` 7 个组件类 + `组件测试/索缆锚锭.py`），任何重建都保持颜色。**注意：pyp3d 的 Attr 只能存标量/字符串，颜色必须以 "r,g,b,a" 字符串形式写入属性**——直接写元组会导致 `该类型尚未注册序列化方法` 错误、组件放置失败。

## 10. 执行建模指令后 BIMBase 崩溃

### 现象

AI 面板执行建模指令后，BIMBase 闪退或弹"程序异常报告"。

### 原因

CADBoard 与 AI_Modeling 各有一个 `bimbase_sync.py`，pyp3d 用"模块名.类名"（如 `bimbase_sync.ApproachPierComponent`）引用组件类。两个同名模块共存时，BIMBase 回调/序列化会解析到错误的模块，导致崩溃。

### 处理方法

已将 `AI_Modeling/bimbase_sync.py` 改名为 `AI_Modeling/aim_bimbase_sync.py`（同步更新 `component_factory.py`、`test_place_to.py`、`ai_modeling_launcher.py` 的引用），彻底消除同名冲突。**注意：改名前放置的 AI 组件在旧模型文件中可能无法解析，需重新生成。**


## 11. AI 布置指令"完全没反应"或"解析成功但放置失败"

### 现象

画板 AI 面板输入"生成一个圆柱""沿X轴每隔500布置5个门式桥墩"等指令后：画板/场景毫无变化，或 BIMBase 已生成组件但面板报"AI_Modeling 执行后未检测到新实体"。

### 原因

- **指令被吞**：`_should_use_local` 只有画板 2D 解析器返回 None 时才尝试 AI_Modeling 建模解析器，画板解析器把 3D 指令（如"生成一个圆柱"）误当成画板画圆，建模链路永远收不到。
- **成功判定误报**：`ai_modeling_launcher.execute_modeling_action` 的 create 成功判定靠实体计数 `after > before`，实体计数 API 不可用返回 -1 时必然误判失败（copy/delete 分支有 `before < 0` 兜底，create 没有）。

### 处理方法（已修复）

- `ai_panel.py` 新增 `_prefer_modeling`：文本未明确说"画板"且命中 3D 组件词时优先走建模链路；纯 2D 图形词（直线/圆/矩形等）仍走画板。
- `ai_modeling_launcher.py` create 分支补 `before < 0` 兜底：实体计数不可用且执行无异常即视为成功。

## 12. 沿路线布置组件不随切向旋转 / 沿组件路径布置报"无法解析路径描述"

### 原因

`AI_Modeling/ai_modeling/component_path.py` 历史上是占位桩（真实实现从未入库）：`orient_component` 不旋转、`resolve_path_name` 返回 None、`build_oriented_components` 返回空列表。

### 处理方法（已修复）

已实现真实逻辑：按宿主参数推断路径（顶/底/棱边/中线/X轴），等距采样生成放置帧，`orient_component` 按 `atan2(dy,dx)`（弧度）绕 Z 轴旋转组件对齐切向。

## 13. 从 BIMBase 读回球体失败 / 同类型组件多于 2 个时读回失败

### 原因

- `bimbase_sync.py` 的 `CADBOARD_TYPES` 集合漏了"球体"，球体虽能被类型推断识别，却在框选处理和回退扫描两处都被跳过。
- `_match_and_update_entity` 多候选匹配时 `_get_params_position` 不覆盖四种实体类型导致全部候选被跳过，直接返回失败。

### 处理方法（已修复）

- `CADBOARD_TYPES` 补"球体"；多候选匹配无位置结果时回退取第一个候选。

## 14. component_registry.json 一条坏记录导致全部注册信息丢失

### 原因

`component_registry.py` 的 `_load_from_file` 把整个加载循环放在一个静默 `try/except` 里，JSON 损坏或任意一条记录异常会丢弃全部记录且无日志。

### 处理方法（已修复）

改为逐条容错：JSON 损坏只放弃本次加载并提示；单条坏记录跳过并提示，不影响其余记录。

## 15. 改名前放置的 AI 组件无法改参/复制（条目 10 的后续）

### 原因

`AI_Modeling/bimbase_sync.py` 改名 `aim_bimbase_sync.py` 后，旧模型文件中实体的序列化引用仍是 `bimbase_sync.XxxComponent`，类解析失败。

### 处理方法（已修复）

- `aim_bimbase_sync.py` 加载时若 `sys.modules` 无 `bimbase_sync` 则注册同名别名指向自身（CADBoard 同名模块已加载时不覆盖）。
- `component_factory.resolve_legacy_component_class`：按类名字符串在 aim_bimbase_sync 中兜底查找。
